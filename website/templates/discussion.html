LAB 3 · PART II

Know your library.

A short walkthrough for the database discussion.

1. Start with the schema

AUTHOR is the parent table. Its primary key is author_id. BOOK is the child table. Its primary key is book_id, and its foreign key author_id references the author.

AUTHOR (author_id, name, country)
BOOK   (book_id, title, price, author_id)

One author can have many books. Each book in this app must have one existing author because its foreign key is NOT NULL.

2. Explain each data type

INT stores IDs. VARCHAR stores names, titles and countries. DECIMAL(10,2) stores prices exactly, with 10 total digits and 2 after the decimal point. NOT NULL prevents missing values. Form validation also prevents empty text.

3. Show the two tables

SELECT book_id, title, price, author_id FROM BOOK;
SELECT author_id, name, country FROM AUTHOR;

The website uses two separate queries. Book counts and display ordering happen in Python. There is no JOIN, GROUP BY or HAVING.

4. Add, edit and remove

Add an author with ID 9001, then a book with ID 9001 belonging to that author. Edit the title, price or author. Edit the author's name or country. Remove the book, then show that the author remains.

INSERT INTO AUTHOR (author_id, name, country)
VALUES (9001, 'Discussion Author', 'Egypt');

UPDATE BOOK SET price = 22.50 WHERE book_id = 9001;

DELETE FROM BOOK WHERE book_id = 9001;

Forms send values separately from the SQL using %s placeholders. The connector safely treats input as data. A WHERE condition limits each edit or removal to the chosen row.

5. Demonstrate cascade deletion

Add a second temporary book for author 9001. Open the author's Remove page and review the affected books. Confirm removal. The author and their books disappear in both the website and DBeaver.

FOREIGN KEY (author_id) REFERENCES AUTHOR(author_id)
    ON DELETE CASCADE

The app sends only the author's DELETE. MySQL removes the related book rows automatically. A foreign key value that points to a nonexistent author causes MySQL error 1452.

6. Show both image bonuses

Upload a cover when adding or editing a book. Upload a photo when adding or editing an author. Reload the collection to show both images persist. Images are kept in local files named after record IDs, so the database still has exactly two tables. The app removes matching image files when records are removed through the website.

Images must be PNG, JPG or WebP, smaller than 5 MB and at most 20 megapixels. The app verifies the image contents instead of trusting the filename.

Ready for the discussion

Run problem2_DDL.sql then problem2_DML.sql to restore the original 3 authors and 6 books. The DDL replaces the assignment database, so use it only when you intend to reset the data.

SQL and uploaded images are stored separately. If you reset the database, use python manage.py reset to reset records and clear old uploaded images together.
